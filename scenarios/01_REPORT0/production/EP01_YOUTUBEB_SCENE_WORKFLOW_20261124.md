# REPORT:0 第1話 — YouTube-b方式への制作工程切替（2026-11-24）

## 従来のYouTube-bとの比較

YouTube-bの試作では、約5秒の映像素材を元に短い動画（15秒、6ショット構成）をFFmpegで編集・合成する**短尺先行**の工程を採用していた。これに対し、本作品の第1話は**8分30秒（510秒）／全43カット／7シーン／日本語39セリフ**と制作量が大きい。

今回まで、映像本体が揃うよりも前に長尺アニマティック・TTS・編集表・QC・ツール作成を繰り返していたため、「見られる映像」がなかなか増えなかった。YouTube-bと同じ発想で、シーン単位で再生可能なMP4を先に仕上げる方式に切り替える。

## 本日完了した実作業（制作物）

1. **20秒の9:16縦型予告映像を実際にMP4出力。** `REPORT0_EP01_YOUTUBEB_STYLE_TEASER_20s.mp4`、720×1280、H.264/AAC、20.000秒。既存V3の0:40〜0:58の日本語音声と、オリジナルの動くUIグラフィックを合成。
2. 予告映像内で**内部3AIのHOLD**と**公開システムの確率100%表示**を区別。100%表示を医学上の死亡確認と断定しない。20秒予告は実写映像ではなく**モーショングラフィック**。
3. **8分30秒・音声付きV3アニマティックを7つのMP4に分割**し、各ファイルの再生時間・映像／音声／日本語字幕ストリームを検証した。
4. ZIP `REPORT0_EP01_SCENE_PREVIEWS_AND_SHORT.zip` に20秒予告、7シーンMP4、シーン台帳、映像制作コード、READMEを収録してChatGPT会話へ納品。ZIP整合性テスト成功。
5. これからの工程を**シーンの完成→セリフ・人物・映像の検収→510秒全編に統合**へ変更する。完了していない実写化を「完成」と誤認しない。

## シーン別制作スプリント運用

- 初回スプリント：01-01（0〜65秒）を最優先。死亡予告の導入→3AI合議HOLD→PUBLIC予告→登場人物の反応までを正式映像化し、音声・字幕と同期させる。
- 1シーンの完成判定：その尺に必要な映像・音声・字幕が全て存在し、人物連続性、INTERNAL／PUBLICの区別、読み上げ、色調、音量、物語の因果が検収済み。
- 完成シーンから本編510秒に挿入し、後続シーンに進む。最後に全体の映像・音声・字幕を再検収。
- [Draft PR #2](https://github.com/tks-gundam-rx93/DEATH_GAME/pull/2) で技術変更を管理し、[Issue #3](https://github.com/tks-gundam-rx93/DEATH_GAME/issues/3) で実写風素材の取得と残32カットを追跡。Owner承認なくmainにマージしない。
